Fungible Token Covenant Specification (KCC20)

A developer proposed a minimal specification interface called KCC20 for fungible token covenants on Kaspa following the Toccata hard fork, sparking community discussion on handling features like minting, burning, and wallet integration.

Why it matters

Establishing a shared token covenant standard is crucial for ensuring interoperability and consistency across wallets and tools as native assets emerge on Kaspa.

Proof-gated covenant ownership of KCC20 state: worked profile + TN10 receipts

A developer shared a reference implementation and testnet receipts for a zero-knowledge-proof-gated covenant owning KCC20 state on TN10, utilizing a two-transition authorize and execute pattern.

Why it matters

It demonstrates a keyless, ZK-proof-gated ownership model for KCC20 state running on testnet, showcasing new covenant capabilities for the ecosystem.

4 Governance 🔥 Trending

KCC-02: Control Principal References in Program ABIs

Contributors proposed KCC-02 to standardize the concept of ownership and principal references within Program ABIs for covenants. Discussion focused on identifying principal roles, maintaining distinct identifiers for covenant lineages versus executable code, and ensuring wallets can verify on-chain state.

Why it matters

This standard is crucial for wallets and developers to reliably track ownership and control across both simple addresses and complex covenant programs.
